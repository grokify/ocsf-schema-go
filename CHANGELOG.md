## [v0.2.0] - 2026-10-29

### Highlights

- Generated events validate strictly as produced: unused profile attributes are no longer written as null, classes keep the Unknown (0) and Other (99) enum values, `unmapped` accepts any keys, and Base Event is a concrete class with class_uid 0

### Added

- [events] `ClassUIDBaseEvent` (0) and Base Event entries in the class registry (`NewEventByClassUID`, `ClassNames`, `ClassCaptions`) ([`68be5b8`](https://github.com/grokify/ocsf-schema-go/commit/68be5b8))

### Fixed

- [gen] Attributes a profile mixes in, such as `cloud` and `osint`, carry `omitempty`; an event without the profile was written with `"cloud": null` and `"osint": null` ([`b6bb307`](https://github.com/grokify/ocsf-schema-go/commit/b6bb307))
- [schema] Enums are merged down the `extends` chain instead of replaced, so classes and objects keep the dictionary's Unknown (0) and Other (99): `authentication.activity_id`, `status_id` and `managed_entity.type_id` among others now accept them and generate their constants ([`a6edca6`](https://github.com/grokify/ocsf-schema-go/commit/a6edca6))
- [schema] Base Event is concrete with class_uid 0 and category_uid 0, as the OCSF schema server lists it, so `ValidateEvent` dispatches events with class_uid 0 ([`68be5b8`](https://github.com/grokify/ocsf-schema-go/commit/68be5b8))
- [validate] The generic object type (`unmapped`, `xattributes`) accepts any keys when unknown attributes are errors, and still must be a JSON object ([`9f350cd`](https://github.com/grokify/ocsf-schema-go/commit/9f350cd))

### Documentation

- README and TRD describe profile `omitempty`, enum refinement and Base Event ([`b905654`](https://github.com/grokify/ocsf-schema-go/commit/b905654))

### Tests

- Regression tests against the embedded schema for profile attributes, inherited enum values, `unmapped` and Base Event ([`a47f2d5`](https://github.com/grokify/ocsf-schema-go/commit/a47f2d5))

## [v0.1.0] - 2026-10-13 ([`9e2d930`](https://github.com/grokify/ocsf-schema-go/commit/9e2d930))

### Highlights

- Initial release: a Go implementation of the OCSF standard covering schema compilation, generated bindings for every event class and object, semantic validation, and `record_integrity` cryptography
- Generated from OCSF 1.10.0-dev, including the `win`, `linux`, and `macos` platform extensions
- Compiled schema embedded in the module, so validation needs no OCSF checkout at runtime

### Added

- [schema] Loader and compiler for OCSF's metaschema source format: `extends` flattening, `$include` profiles, dictionary type joins, platform extensions, external extension roots, class-UID computation, and observable enum synthesis ([`b65919c`](https://github.com/grokify/ocsf-schema-go/commit/b65919c))
- [gen] Go code generator emitting structs, enum constants, caption maps, and the class-UID registry from a compiled schema ([`56d3bb6`](https://github.com/grokify/ocsf-schema-go/commit/56d3bb6))
- [cmd/ocsfgen] Cobra CLI to regenerate bindings from any OCSF schema checkout, with `--extensions` and `--extension-dirs` flags ([`56d3bb6`](https://github.com/grokify/ocsf-schema-go/commit/56d3bb6))
- [ocsf/events, ocsf/objects] Generated event and object structs with caption lookup tables, observable type registries, and the `NewEventByClassUID` / `UnmarshalEvent` class-UID dispatcher ([`68b4d1d`](https://github.com/grokify/ocsf-schema-go/commit/68b4d1d))
- [ocsf/ocsfdata] Embedded compiled schema as indented JSON (`MustSchema()`) for runtime use without an OCSF checkout ([`68b4d1d`](https://github.com/grokify/ocsf-schema-go/commit/68b4d1d))
- [validate] Semantic validator: profile-aware required attributes, scalar types, enum membership, nested objects, `at_least_one`/`just_one` constraints, and class/category/type UID consistency ([`9a34cbc`](https://github.com/grokify/ocsf-schema-go/commit/9a34cbc))
- [recordintegrity] `record_integrity` profile cryptography: JCS (RFC 8785) canonicalization, content and chain fingerprints, ECDSA/RSA attestation signing, verification with a status taxonomy, and tamper-evident chain-link verification ([`ccff37f`](https://github.com/grokify/ocsf-schema-go/commit/ccff37f))
- [ocsfext/integrity] Schema extension adding `digital_signature.signature_value`, which OCSF 1.10.0-dev lacks; interim until upstream ocsf-schema#1698 lands an official attribute ([`15d7ac2`](https://github.com/grokify/ocsf-schema-go/commit/15d7ac2))

### Documentation

- README, MkDocs site, PRD/TRD/PLAN/ROADMAP specs, and upstream issue draft for ocsf-schema#1698 ([`9e2d930`](https://github.com/grokify/ocsf-schema-go/commit/9e2d930))
