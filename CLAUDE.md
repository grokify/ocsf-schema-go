# CLAUDE.md — ocsf-schema-go

Guidance for working in this repository.

## What this repo is

ocsf-schema-go is the **Go implementation of the OCSF standard**
(https://github.com/ocsf/ocsf-schema): a compiler for OCSF's metaschema source
format, generated Go bindings for every event class and object, a semantic
validator, and the `record_integrity` cryptography. It contains **no storage or
application logic** — that lives in `github.com/grokify/ocsf-lake`, which depends on
this module. Keep that boundary: anything derived from the OCSF spec belongs here;
anything about persistence/ingestion belongs in ocsf-lake.

## Architecture

| Package | Role |
|---------|------|
| `schema` | Loads an OCSF source tree and compiles it: `extends` flattening, `$include` profiles, dictionary type joins, platform extensions (incl. external extension dirs), class-UID computation, observable enum synthesis |
| `validate` | Semantic validator over a compiled schema: required attrs (profile-aware), types, enums, constraints, UID consistency |
| `recordintegrity` | record_integrity crypto: JCS (RFC 8785) canonicalization, fingerprints, sign/verify (ECDSA/RSA), chain links. Content fingerprints exclude `attestation_list`; chain fingerprints include it |
| `gen` | Code generator emitting the `ocsf/` packages |
| `cmd/ocsfgen` | CLI over gen |
| `ocsf/objects`, `ocsf/events` | **Generated — DO NOT EDIT.** Structs, constants, caption maps, class-UID registry |
| `ocsf/ocsfdata` | **Generated.** Embedded indented JSON of the compiled schema (`MustSchema()`), used for runtime validation with no OCSF checkout |
| `ocsfext/integrity` | Our schema extension adding `digital_signature.signature_value` — interim until upstream ocsf-schema#1698 lands an official attribute (see `docs/upstream/signature-value-issue-1698.md`) |

## Regenerating the bindings

```bash
go run ./cmd/ocsfgen generate \
  --schema-dir /path/to/ocsf/ocsf-schema \
  --out ocsf \
  --extension-dirs ocsfext/integrity
```

Platform extensions (win/linux/macos) are included by default. Always regenerate
with `--extension-dirs ocsfext/integrity` — the `recordintegrity` package depends on
the `SignatureValue` field it adds. Commit regenerated output together with the
change that motivated it.

## Commands

```bash
go build ./... && go test ./...
golangci-lint run
OCSF_SCHEMA_DIR=/path/to/ocsf-schema go test ./schema/ ./validate/   # opt-in full-tree tests
```

## Conventions and gotchas

- Generated files carry `Code generated by ocsfgen ... DO NOT EDIT`; change the
  generator (`gen/`) or the schema inputs instead.
- The OCSF source format is **not** JSON Schema: attribute types come from
  `dictionary.json`; `observable.type_id`'s full enum is *synthesized* from
  `observable:` annotations (the source file only declares 0/99).
- Schema is currently generated from OCSF **1.10.0-dev** (unreleased); the
  `record_integrity` profile does not exist in stable releases, so do not
  regenerate from a stable tag without checking `docs/specs/ROADMAP.md`.
- `schema.Attribute.Source` serializes as `_source` — profile/extension provenance
  must survive the ocsfdata embed round-trip (the validator's profile-aware
  requirement logic depends on it).
- Never commit key material; recordintegrity tests generate keys per run.
