# Release Notes v0.1.0

**Release Date:** October 13, 2026

## Overview

This is the initial release of ocsf-schema-go, the Go implementation of the
[Open Cybersecurity Schema Framework (OCSF)](https://github.com/ocsf/ocsf-schema).
It compiles OCSF's metaschema source format, generates idiomatic Go bindings for every
event class and object, validates events against the real schema semantics, and
implements the cryptography of the `record_integrity` profile.

The module contains no storage or application logic; persistence and ingestion belong
in downstream modules such as `github.com/grokify/ocsf-lake`.

## Installation

```bash
go get github.com/grokify/ocsf-schema-go@v0.1.0
```

To regenerate the bindings from an OCSF checkout:

```bash
go run github.com/grokify/ocsf-schema-go/cmd/ocsfgen@v0.1.0 generate \
  --schema-dir /path/to/ocsf-schema \
  --out ocsf \
  --extension-dirs ocsfext/integrity
```

## Highlights

- Complete OCSF 1.10.0-dev bindings, including the `win`, `linux`, and `macos` platform extensions
- Semantic validator driven by an embedded compiled schema, requiring no OCSF checkout at runtime
- `record_integrity` signing, verification, and tamper-evident chaining

## Features

### Schema compiler (`schema`)

Loads an OCSF source tree and compiles it: `extends` flattening, `$include` profiles,
dictionary type joins, platform extensions, external extension roots, class-UID
computation, and observable enum synthesis.

### Generated bindings (`ocsf/events`, `ocsf/objects`, `ocsf/ocsfdata`)

- Structs for every event class and object; attributes marshal to OCSF snake_case,
  required attributes unconditionally and others with `omitempty`
- Enum constants with per-enum `*Captions` maps, plus `ClassNames`, `ClassCaptions`,
  and `CategoryCaptions`
- Class-UID registry: `NewEventByClassUID` and `UnmarshalEvent`
- Observable type registries: `ObservableTypeIDBy{Attribute,DictionaryType,Object}`
- Embedded compiled schema (indented JSON) via `ocsfdata.MustSchema()`

### Validator (`validate`)

Checks profile-aware required attributes, scalar types, enum membership, nested
objects, `at_least_one`/`just_one` constraints, and `class_uid`/`category_uid`/`type_uid`
consistency.

```go
v := validate.New(ocsfdata.MustSchema())
result := v.ValidateEvent(eventJSON)
if !result.Valid() {
    for _, issue := range result.Errors() {
        log.Println(issue)
    }
}
```

### Record integrity (`recordintegrity`)

- JCS (RFC 8785) canonicalization and SHA-256 fingerprints; content fingerprints
  exclude `attestation_list`, chain fingerprints include it
- ECDSA and RSA attestation signing with signer certificate metadata
- Verification with a status taxonomy: `verified`, `unsigned`, `fingerprint_mismatch`,
  `signature_invalid`, `cert_untrusted`, `cert_expired`, `chain_broken`, `malformed`
- Tamper-evident chain-link verification via `VerifyLink`

### Integrity extension (`ocsfext/integrity`)

OCSF 1.10.0-dev defines `digital_signature` metadata but no attribute for the signature
bytes. This extension adds `digital_signature.signature_value` and will be retired
once upstream ocsf-schema#1698 lands an official attribute.

### Code generator (`gen`, `cmd/ocsfgen`)

The `ocsfgen` CLI regenerates the bindings from any OCSF schema checkout, with
`--extensions` for platform extension selection and `--extension-dirs` for external
extension roots.

## Known Limitations

- The validator does not check regex, range, or `max_len` facets of dictionary types
- Generation is not yet pinned to tagged OCSF releases; the schema is generated from
  the unreleased 1.10.0-dev because the `record_integrity` profile is absent from
  stable releases

See `docs/specs/ROADMAP.md` for planned work.
