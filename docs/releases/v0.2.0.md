# Release Notes v0.2.0

**Release Date:** October 29, 2026

## Overview

A release that makes events built with the generated types validate strictly as
they are produced. It fixes four places where the compiled schema, the generated
bindings or the validator differed from how the OCSF schema server presents OCSF.

## Installation

```bash
go get github.com/grokify/ocsf-schema-go@v0.2.0
```

## Fixes

- **Unused profiles are not written as null.** Attributes a profile mixes in, such
  as `cloud` and `osint`, are required only when the event declares the profile in
  `metadata.profiles`. They now carry `omitempty`, so an event without the profile
  no longer contains `"cloud": null` and `"osint": null`.
- **Enums keep Unknown and Other.** A class or object that lists its own values for
  an enum attribute now refines the inherited enum instead of replacing it, from the
  dictionary through each ancestor to the class. `authentication.activity_id` is
  0–7 and 99, `status_id` is 0, 1, 2 and 99, and `managed_entity.type_id` is 0–7
  and 99, matching the OCSF schema server. Events using 0 or 99 validate, and the
  generated `...Unknown` and `...Other` constants exist for every such attribute.
- **`unmapped` holds any keys.** The validator checked the generic object type
  (`unmapped`, `xattributes`) as an object with no attributes, so with
  `WithUnknownAttributes(UnknownError)` every key inside `unmapped` was an error. It
  now accepts any keys there and still requires a JSON object.
- **Base Event is a class.** `base_event` is concrete with `class_uid` 0 and
  `category_uid` 0, as the OCSF schema server lists it. `ClassUIDBaseEvent` is
  generated, the class registry includes it, and `ValidateEvent` dispatches events
  with `class_uid` 0. Category bases such as `iam` stay abstract.

## Upgrading

- JSON produced from the generated types no longer contains `cloud` or `osint` when
  they are unset. Code that set them is unaffected.
- The validator accepts values it rejected before (0 and 99 on refined enums, keys
  inside `unmapped`, `class_uid` 0). A pipeline that relied on those rejections
  should check its inputs another way.
- The bindings are regenerated from the same OCSF schema (1.10.0-dev) as v0.1.0.
